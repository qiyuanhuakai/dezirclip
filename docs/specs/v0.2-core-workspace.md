# v0.2 P2-A：Workspace 与共享 Core

本阶段将桌面与独立 CLI 已经共同使用的业务实现移入真实 Rust crate。Workspace 提取不额外变更父分支的数据库 schema、设置键、CLI 参数与 MCP JSON 协议；没有引入常驻服务或 IPC。

## 依赖与实现归属

```text
dezirclip desktop / dzc CLI
    ├── dzc-core
    └── dzc-platform ──> dzc-core
```

`crates/dzc-core/src/` 包含 `domain`、`database`、`infrastructure/repository`、附件和数据目录规则、`services/search`、`services/backup`，以及加密格式和敏感内容保护策略。原实现移动后，`src-tauri/src/` 对应模块仅作 re-export。桌面命令和 CLI 因而使用同一套存储、查询、备份和敏感标签逻辑，没有跨 crate 的 `#[path]` 引用。

Core 保留 SQLite、文件读写、图片解码等业务依赖，不依赖 Tauri、GTK、WebView、Keyring 或原生剪贴板库。Core 和普通 CLI 的依赖图不包含 HTTP 客户端。纯 Core 可单独编译、测试和运行 `headless` 示例。

`crates/dzc-platform/src/` 包含 Windows DPAPI、Linux Keyring/兼容密钥迁移、原生剪贴板、文件 URI 与本地剪贴板内容适配。平台 crate 依赖 Core 的 `KeyProvider` 接口；Core 不反向依赖平台。现有 Desktop 平台监听器、热键、窗口跟踪器仍在 `src-tauri/src/infrastructure`。

整合 P0-B 后，schema 19 的可见性函数、原子敏感转换和 HTML 附件计划统一位于 Core；通用 regular/bounded/no-follow 文件读取也归入 Core，Platform 仅作薄导出。Core 的 Linux 文件打开 flags 使用 libc，不依赖剪贴板、Keyring 或 GUI。HTML 计划返回 Result，预算为单图 16 MiB、合计 32 MiB、64 个引用，失败时不创建附件。为当前 Desktop pipeline 兼容，`save_capture_with_conn`、`HtmlAttachmentPlan`、可见性注册及敏感记录验证保留临时公开桥。它们不属于已冻结 facade，P2-B/P2-C 再收敛到专用业务接口。

## 密钥与诊断边界

`dzc_core::infrastructure::encryption::KeyProvider` 提供文本加密和解密。Desktop 与 CLI 入口在处理命令前安装 `dzc_platform::NativeKeyProvider`；注册本身不访问 Keyring。原有 `dpapi:`、`linux:`、兼容密文格式及敏感写入失败关闭规则保留。

未安装 provider 的生产 Core 返回 `KeyUnavailable`，不会把敏感正文当作明文保存。provider 若返回明文或不完整的已知密文 envelope，Core 返回 `EncryptionFailed`。Core 单元测试中的确定性 provider 仅用于测试，不会进入生产依赖。平台测试单独验证 Windows DPAPI 或注入的 Linux Keyring 存储行为；Linux 注入测试不等于真实桌面 Keyring 解锁、重启验收。

平台诊断通过可注入的 `fn(&str)` sink 输出，Desktop/CLI 连接现有诊断日志。Core 不导入应用 logger。诊断中不新增正文输出。

## Workspace 与分发

根目录 `Cargo.toml` 统一版本、依赖和 release profile，唯一 lock 文件移到根目录。`src-tauri`、`dzc-core`、`dzc-platform` 继承 workspace 版本。保留 `lto=true`、`codegen-units=1`、`opt-level="s"`、`strip=true`、`panic="abort"`。

默认输出目录改为根目录 `target/`，显式 `--target-dir`、`CARGO_TARGET_DIR` 仍可覆盖。Sidecar 构建从 Cargo metadata 获取目录并使用 `--no-default-features`；portable、Flatpak、CLI 包装器和已有 CI cache/二进制断言同步到 workspace。独立 Linux 构建的隔离源码包含根 manifest/lock、两个 crate 和原资源，不包含任一 target 目录。版本脚本同步更新三个本地包的 lock 条目，发布版本修改后仍可使用 `--locked`。

兼容构建命令仍有效：

```powershell
cargo build --manifest-path src-tauri/Cargo.toml --no-default-features --bin dzc
cargo test -p dzc-core -p dzc-platform --lib
cargo run -p dzc-core --example headless
cargo check --workspace --all-targets
python -m unittest discover -s scripts/tests -v
```

## 本阶段验收与限制

在 Windows x86_64 与 WSL Ubuntu x86_64 使用独立 target 运行：

| 验证 | Windows | Linux |
|---|---|---|
| Core 单元测试 | 165 通过 | 163 通过 |
| Platform 单元测试 | 9 通过，1 个性能测试忽略 | 25 通过 |
| 独立 CLI 编译 | 通过 | 通过 |
| 真实 CLI/MCP 端到端协议测试 | 8 通过，1 个可选 PTY 场景跳过 | 8 通过，1 个平台场景跳过 |
| 全 Workspace 所有 target 编译检查 | 通过 | 通过 |

Windows 额外运行了未启用 desktop 的应用库与 CLI 测试（103 + 4 通过，1 个性能测试忽略），以及生产 Core `headless` 示例。Windows 脚本套件共 25 个测试，24 通过、Flatpak Debian 工具场景跳过；Linux 脚本套件 21 通过、4 个依赖 Node/PowerShell 的场景跳过。测试覆盖本地包版本继承、缺少 lock 时不修改版本、分发资源和兼容性断言。使用 standalone 脚本的真实 tar 选择导出隔离源码目录，确认三个 workspace member 均来自隔离目录，并成功执行 `--locked --no-default-features` CLI 编译检查。现有截图命令重复测试属性等警告未在此阶段修改。

本地未执行 Windows ARM64、Linux ARM64、Ubuntu 22.04 Docker release 兼容构建、签名安装器或 GUI 启动验收。完整平台构建矩阵和分发兼容检查继续由已有工作流执行；本地 debug 构建不能作为最低发行版 ABI 保证。Linux 编译通过也不代表真实 X11/Wayland 会话能力已验收。

## 可重复采样与后续阶段

`scripts/sample-history-latency.py` 使用独立临时数据库和合成数据，测量 CLI 启动、历史查询及 JSON 输出的组合延迟，并记录二进制 SHA256、版本、主机、每次样本和 p50/p95。示例：

```powershell
python scripts/sample-history-latency.py --binary target/debug/dzc.exe --rows 1000 --iterations 10 --output .harness/perf/history.json
```

本次 Windows debug 单次采样：metadata list 的 p50/p95 为 66.04/72.04 ms，search 为 64.32/66.25 ms（1000 行、10 次，另有预热）。这只是后续可复现的起始记录；没有相同环境下提取前的对照，因此不宣称性能提升或无回退，也不覆盖采集、GUI 延迟、内存和原生剪贴板。

P2-B 从 `src-tauri/src/services/clipboard/{mod,pipeline,utils}.rs` 提取真实 CaptureEngine 与 EventSink，解除 AppHandle 依赖；窗口显示、提示音、OCR/粘贴队列调度保留 Desktop adapter。Windows listener 当前在 `services/clipboard_listener.rs`，Linux listener 在 `infrastructure/linux_api/clipboard_listener.rs`。P2-C 再稳定 ports/facade。当前兼容 re-export 和少量 legacy adapter 的 cache invalidation 接口不代表最终公共 API 已冻结。
