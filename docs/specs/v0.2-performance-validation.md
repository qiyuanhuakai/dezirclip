## 写入与手工敏感标签请求

`scripts/sample-write-latency.py` 在 1000 和 10000 条普通合成历史上分别采样 `add -`（1 MiB UTF-8/CRLF stdin）、`add @文件`（同一内容）及 `tag add ID sensitive`。每次操作使用模板数据库的新副本，模板创建、复制、后置核对均不计时，避免测到不断增长的历史。核对 add 的完整字节和记录数量，并记录 sensitive 请求完成后正文/预览是否加密、该行 payload 是否仍可由 FTS 命中。

旧版 CLI 的 tag 命令仅写标签，桌面应用另有异步加密队列。因此同命令的延迟是用户请求成本对照，不是具有相同安全后置条件的敏感转换对照。旧版未加密状态会明确出现在 JSON 中。最终二进制额外使用 `--require-protected-conversion`，若返回成功后仍有明文字段或 FTS 敏感正文，则记录失败并退出非零。安全成本增加不能被旧版提前返回的低延迟掩盖。

```powershell
python scripts/sample-write-latency.py --binary .harness/perf-baseline-bin/802808b/debug/dzc.exe --rows 10000 --iterations 50 --source-revision 802808b06e6b795064c5065d1d880bae9b193b9a --build-profile debug --target x86_64-pc-windows-msvc --output .harness/perf/baseline-write-10k.json
python scripts/sample-write-latency.py --binary .harness/perf-final-bin/debug/dzc.exe --rows 10000 --iterations 50 --source-revision FINAL_COMMIT --build-profile debug --target x86_64-pc-windows-msvc --baseline .harness/perf/baseline-write-10k.json --require-protected-conversion --output .harness/perf/final-write-10k.json
```

两条命令对 1000 行重复一次。此前 schema 19 的转换仍需全库 FTS 维护，schema 20 改为按记录安全删除；最终报告仍须展示 1k/10k 两档 add 与 tag 的 p50/p95、门槛及加密/FTS 后置状态，不能只凭 list/search 通过就验收。这组 CLI 写入样本仍不包含 OS reader、CaptureEngine、事件和加密队列等待，完整捕获验收继续单列。

基线另已实际执行每项 5 次预热加 50 次正式样本，保留于 `.harness/perf/baseline-802808b-write-{1k,10k}-50-windows-debug.json`：

## 捕获与敏感转换的独立采样方案

以下路径仍未验证，不包含在历史查询样本的门槛结论中：

| 路径 | 计时边界 | 数据与后置条件 |
|---|---|---|
| 普通捕获 | 已获得 reader payload 至数据库提交和 metadata event 发出 | 200 B/10 KiB/1 MiB 文本、含 HTML 的富文本、4K 图片；核对正文、HTML、去重行、附件哈希及事件数量 |
| 重复捕获 | 去重查询开始至已有记录更新时间提交 | 原始 CRLF/空白文本、普通和手工敏感标签；相同 ID，标签不丢失，敏感正文保持加密 |
| 敏感新捕获 | 隐私预检开始至加密提交 | 短文本、500 B 文本、正文加 3 KiB HTML；核对三字段密文、可解密正文、标签与 FTS 一致性 |
| 敏感转换 | 用户标签请求开始至密文/索引事务完成；队列等待另计 | 单条与 20 条突发，记录请求、排队、锁等待、提交时间；在转换期间交错普通捕获并单独比较捕获 p95 |
| 隐私拒绝 | 元数据预检开始至拒绝事件 | 敏感来源、标记或暂停策略，断言未读取 payload、未写 DB/附件、无正文事件 |

先做无 GUI 的真实业务 harness：相同确定性输入、独立临时目录、真实 SQLite 与 Windows DPAPI，使用生产 repository/engine 方法，不把 SQL seed 放入计时段。Core 的确定性测试 provider 不可用作原生加密性能证据。现有忽略的 `dpapi_per_value_cost` 只输出原语平均值，缺少 SQL、事务、队列和 p95，不能代替敏感转换验收。

旧版捕获流水线依赖 AppHandle，最终 P2-B 引擎不依赖。对照 adapter 必须明确共同的起止点：先记录共同的 repository save/hash/dedup 子路径，再在隔离 Desktop 实例测完整 capture。不能将旧版的异步入队返回时间与新版完成加密的时间直接比较。若旧版安全行为与新版不同，应比较具有相同安全后置条件的操作，分别报告新增保护成本；拒绝路径以正确性为前提。

完整 Desktop 样本需要预备隔离应用与专用虚拟剪贴板会话，关闭真实用户实例；样本覆盖 metadata/read、engine、DB 和 event 分段时间。现有 CDP 工具只说明面板响应、列表渲染和启动，不证明后台捕获路径。未获得这种环境或等价的 reader 注入执行前，该项继续标为未验证。
