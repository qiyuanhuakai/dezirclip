# Shared Host clients

The desktop starts an Embedded Host in the existing GUI process. Ordinary list,
preview and mutation operations call Core through owned Rust values. Its passive
local listener permits an explicitly authorized CLI or Surface to connect; it
does not create a daemon. Starting the optional service is a separate user action.

## Lifecycle and identity

Place `dezirclip`, `dzc` and `dzc-service` from the same build in one directory.
Use the same `DEZIRCLIP_DB_PATH` for the GUI and CLI in an isolated profile:

```text
dzc service status --json
dzc service start --json
dzc service stop
```

`start --no-capture` serves history without initializing a native listener. The
controller checks the helper's version, schema, protocol and verified build set
before requesting handoff. Process-exit observation is checked before disturbing
an existing Embedded Host. An unsupported kernel or denied observation fails the
transition; ordinary Embedded operation and standalone history commands remain
available. There is no service executable override or automatic service launch.

Handoff drains the native subscription, queued processing, admitted requests,
original-ticket OCR and native owners. An unconfirmed stop retains ownership.
Workers and follow-up work hold the OS lease independently of the Host object's
lifetime. Linux conservatively uses one capture owner per UID, including display
and database path aliases; it does not claim simultaneous independent graphical
sessions under the same UID. Windows uses the authenticated token's session.

The GUI's `get_clipboard_host_status()` and `dzc service status --json` report:

```text
{mode, capture_owner,
 state:{service_instance_id,history_revision,privacy_epoch,event_sequence},
 privacy:{active,expires_at_ms,privacy_epoch}}
```

History revision and privacy epoch come from persistent Core state. Event
sequence belongs to one Host instance. Every GUI row carries `host_instance_id`;
negative IDs are meaningful only with that original instance. Negative-ID
operations require `expectedHostInstanceId`, including derived copies. A restart
invalidates all WebView selections and reveals even when its numeric epoch is
unchanged. The event ring signals resynchronization instead of silently dropping
state. Events contain metadata, never entry bodies.

## Permissions and bodies

OS peer authentication precedes the protocol handshake. A claimed role grants
no management, body or policy permission. Current-user private control files
hold instance-specific Desktop/CLI credentials; delegated MCP and Surface grants
cannot acquire Desktop permission. All remote policy reads and mutations run in
the actual owner Host, using Core permits and its real RAM session collection.
Native private exports must be revoked successfully before a mutation ACK or
privacy event. Failure remains an error and is retried on the next observation.

Remote Desktop metadata, explicit resource previews and body snapshots use the
single generated wire schema. A snapshot is bound to its authenticated connection,
Host instance and epoch, expires after five seconds, and is limited to four live
snapshots and 32 MiB in total. Reads use 192 KiB chunks on that same connection.
Generated capture uploads have corresponding connection, epoch, lifetime and
aggregate limits, retain the original opaque capture ticket, and never serialize
the ticket. No protocol method exposes a raw database connection, key, arbitrary
setting or local attachment path. The default Embedded path avoids IPC body
serialization. Image and HTML preview representations are authorized Core RAM
values; protected files are copied through scoped kernel-backed native leases.

Pinning or tagging a negative session entry persists a new positive row only
through Core's manual persistence permission, then removes the original RAM item.
An active privacy session requires explicit confirmation and its original epoch;
confirmation never grants sensitive read access. The CLI exposes this intent as
`add/edit --confirm-persistence`. Imports acquire their original ticket before
reading the import file.

Remote manual OCR and external opening of negative session resources report
`RemoteOcrUnavailable` / `SessionExternalOpenUnavailable`. Negative session items
cannot enter the ID-only sequential paste queue or persistent pin ordering.
These paths do not fall back to a stale GUI-local session. Ordinary positive queue
items in Service mode request the owner Host's authorized copy/paste action.
Wayland paste and native shortcuts remain explicitly unavailable when their
native capability is unavailable.

## CLI, MCP and Go

Ordinary CLI commands continue to open Core directly and preserve their existing
JSON format. No-default-features CLI builds do not link Tauri or WebView. The
explicit `dzc mcp --host` mode connects to an existing Host and never falls back to
opening history or starting a service. Summary reads need no body permission.
Ordinary bounded text reads require an explicitly delegated token from
`dzc service grant-mcp`; supply it as `DEZIRCLIP_HOST_GRANT`. Tokens are revocable,
read-only and cannot read protected entries. MCP tools retain their positive-ID
contract; a negative session summary cannot be used as an unbound body reference.

The Go client shares generated DTOs and the offline canonical schema with Rust.
Its `EntryReference` retains the original Host instance, and its metadata cursor
invalidates cached state on instance/epoch changes or an event-ring gap. The same
native client fixture connects to Core-backed Embedded and Service Hosts, reads
metadata, reconnects and requests a resynchronization after a dropped window.

## Verification scope

Host tests exercise real private Named Pipes / UDS, authority separation,
concurrent event waits, admitted stop ACK draining, failed-stop lease retention,
private snapshot fences and actual owner session policy mutations. Inline Core
tests cover metadata projection before body/resource materialization. Canonical
fixtures validate new Desktop actions and public errors in Rust and Go.

`scripts/test-local-host.py` exercises actual no-capture service processes.
`scripts/test-local-clients.py` exercises actual CLI/MCP delegation, revocation,
privacy confirmation and the absence of a direct-database fallback, exclusively
with synthetic profiles. The explicit ignored GUI-backend updater test exercises
verified prepare, real process exit and abort recovery of a no-capture service.
These are functional checks, not idle-load or performance measurements. Native
clipboard and actual WebView lifecycle acceptance use separate isolated native
fixtures; ordinary unit results do not claim cross-account Windows acceptance or
an installed-package upgrade.
