# v0.2.0-alpha.1 发布验收

状态：整合验收中，尚未发布。此文随最终构建补齐冻结提交、原始证据和审查结论。

## 本次范围

alpha.1 交付 Phase 0–2：敏感写入失败关闭与事务原子性、官方签名更新、安装升级安全，以及 Workspace、Core、独立捕获引擎和平台业务接口。GUI 默认直接链接 Core，继续保留独立 dzc、TUI、MCP 和 Quick Paste。

服务与 IPC 属于 alpha.2，隐私模式 2.0 属于 alpha.3，Wayland 实验后端属于 alpha.4。alpha.1 的 Linux 原生桌面支持以 X11 为准；能力报告会说明当前会话不可用的功能。

## 升级与兼容

- Windows 旧版可直接运行新安装器覆盖升级，无需先卸载。新升级路径跳过旧卸载程序，保留安装目录、历史和设置；真正卸载只恢复应用持有且仍匹配的系统修改凭据。
- 运行中的可写 AppImage 支持原位替换；只读安装提供明确不可安装状态。deb、rpm、Flatpak 和独立 CLI 继续使用各自的手动升级方式。
- 自动检查默认关闭，启用后延迟并限频。Stable 接受正式版，Preview 可接受较新的预发布与正式版；安装需要用户明确确认。
- 更新仅使用固定 GitHub HTTPS 资源和内置公钥。敏感业务、Core 与 MCP 保持离线；签名、版本或制品门槛失败时不推进更新通道。
- schema 19 保留已有历史并过滤受保护记录的全文索引。旧程序面对较新的结构拒绝写入；不要用旧 CLI 写入已迁移的数据库。更新前的备份仍需保留。
- 敏感图片和附件在尚无完整二进制保护时明确拒绝持久化。Linux 原生密钥库不可用时保护写入报错；不会降为明文成功。
- 保留主线的独立 Linux CLI glibc 2.28 分发基线。GUI 和独立 CLI 的发行版依赖范围分别验收。

## 审查与统一合并

依用户要求，全部进度先完成、分别审查，最后统一处理合并。功能进度已全部提交独立 PR：安装器 #77、失败关闭 #78、Updater #79、更新界面 #80、事务原子性 #81、Workspace #82、捕获引擎 #84、平台接口 #85。最终整合 PR 完成后补齐。

每个 PR 的通过依据必须对应其当前 head。合并过程保留依赖关系，再对包含全部改动与同期主线更新的实际整合树验收。构建通过不代替 reviewer 对未解决意见的复核。

## 原生验收证据边界

Windows 安装器只在 GitHub 托管的临时 runner 上执行。脚本核对旧包来源与候选制品、真实 GUI/CLI 的同一合成数据库、系统设置凭据和卸载行为；本机用户的安装、注册表与剪贴板不参与验收。

Linux 工具 `scripts/test-native-appimage.py` 在独立用户、PID、网络、X11 和 D-Bus 会话中执行旧包、官方 updater 替换和实际新 WebView。测试公钥与生产签名完全分开。错误 payload、篡改版本、只读位置、旧历史回读及实际渲染均有独立断言。

本地离线替换证明包安装与界面行为，不证明生产网络下载、生产签名或 ARM64 的物理桌面交互。发行工作流仍须逐项完成生产签名和全部目标制品校验，才公开版本与 Preview 索引。
