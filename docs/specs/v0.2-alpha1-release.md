# v0.2.0-alpha.1 发布验收

本地运行源码与性能工具冻结于 `86d4324e94d4395c818dedcf33b391fea207c2b7`，schema 21。以下记录对应这次冻结；实际公开版本与制品见 [v0.2.0-alpha.1 Release](https://github.com/qiyuanhuakai/dezirclip/releases/tag/v0.2.0-alpha.1)。最终验收文档提交不改变既有二进制来源，最终整合 PR 的实际 head、审查与 CI 以 [PR #86](https://github.com/qiyuanhuakai/dezirclip/pull/86) 为准。

## 本次范围

alpha.1 交付 Phase 0–2：敏感写入失败关闭与事务原子性、官方签名更新、安全覆盖安装，以及 Workspace、Core、独立捕获引擎和平台业务接口。GUI 默认直接链接 Core，保留独立 dzc、TUI、只读 MCP 和 Quick Paste，不新增默认常驻服务。

MyGo-Ready 增量提供版本与源提交绑定的构建标识、显式组件信息、Core 受限历史摘要，以及实际更新安装前的 Host 协调边界。Core 不依赖 Tauri 或窗口系统；平台实现 Core 定义的端口。尚无 Surface 参与者，其物理退出与重启不属于本次实测。

Phase 3+ 不包含在本次发布：可选服务与 IPC 属于 alpha.2，隐私模式 2.0 属于 alpha.3，原生 Wayland 实验后端属于 alpha.4。MyGo 客户端和整体 Host 迁移仍是后续方向；当前 Linux 原生桌面范围为 X11。

## 升级与兼容

- Windows 无需先卸载。旧版首次手动迁移时，使用安装器保留现有安装的覆盖选项，或运行 `setup.exe /P /UPDATE`；内置 updater 传入更新参数并跳过旧卸载程序。选择先卸载仍会执行已经固化在旧卸载程序中的清理逻辑。新版本真正卸载只恢复应用持有且仍匹配的系统修改凭据，详见[安装器迁移边界](windows-installer-safety.md#first-migration-from-older-installers)。
- 运行中的可写 AppImage 支持原位替换；只读安装明确报告不可安装。deb、rpm、Flatpak、portable 与独立 CLI 继续使用各自的升级方式。
- 自动检查默认关闭，启用后延迟并限频；下载与安装须用户明确确认。Stable 接受正式版，Preview 在两个固定索引中选择较新的预发布或正式版，不降级。
- 更新仅使用固定 GitHub HTTPS 资源与内置公钥，验证制品、签名及绑定版本。Core、敏感业务和 MCP 保持离线；错误不会推进通道。安装协调失败时拒绝安装并通知恢复，不按名称查找或强杀外部 CLI/进程。见[更新接口与边界](../updater.md)。
- schema 21 保留已有历史、业务字段和密文格式。schema 20 原子迁移清理旧索引并启用 FTS5 按记录安全删除；schema 21 设置公开的 `automerge=8`，不再次重建索引，也不延后敏感词项清理。每个受管理写连接启用 `PRAGMA secure_delete=ON`，生产程序固定使用包含修复的 SQLite 3.54.0。
- 派生索引可进入 FTS 格式 5，只读识别至少需要 SQLite 3.42；这不代表旧引擎混写安全。Windows/Linux 合成 fixture 写入分别使用已验证的 SQLite 3.50.4/3.53.1，曾失败的 3.45.1 跨连接混写证据保留。旧 schema 18/20 CLI 拒绝 schema 21 的 DELETE/WAL 实测通过。保留升级前备份；不承诺追溯擦除旧 WAL、备份或文件系统中所有历史副本。见[索引维护说明](v0.2-sensitive-index-maintenance.md)和[数据安全](../data-safety.md)。
- 敏感正文、预览、HTML、OCR、标签和索引在同一事务中变更。缺少完整二进制保护的敏感图片与附件明确拒绝持久化；Linux 原生密钥库不可用时保护写入报错，不降为明文成功。
- 独立 Linux CLI 保留 glibc 2.28 分发基线；GUI 与 CLI 的发行依赖范围分别验收。

首轮生产发布未公开，记录在 [Release run 39416862919](https://github.com/qiyuanhuakai/dezirclip/actions/runs/39416862919)。它及隔离 RPM 复现暴露三个发布问题：RPM 将正常 Cargo CLI 与同名 external binary 重复加入 `/usr/bin/dzc`；RPM 不接受带连字符的 SemVer 预发布包版本；发布工具用仅查询已发布版本的按 tag 接口读取 draft。修复涉及打包与发布工具，按独立 PR 审查；最终版本须从修复后的实际 tag 提交重新构建，不能将首轮部分制品改标为新提交。失败工作流、草稿元数据与14份已上传制品（44,292,080B）均已单独归档并核对哈希。

RPM 单独通过 `pnpm run tauri:bundle:rpm` 打包，仅此进程使用 Version `0.2.0`、Release `0.alpha.1`；正式版使用 Release `1`，应用、CLI 和更新版本保持 `0.2.0-alpha.1`。该入口限定 Linux 原生 release，拒绝交叉目标；普通 Tauri 构建仍通过现有准备 hook 提供唯一的 Cargo CLI。固定 Tauri 2.12.3 的真实隔离 RPM 已验证唯一 `/usr/bin/dzc` 与原准备输入逐字节相同、Version/Release 符合映射。它使用原86d只读二进制，未重编或改标签，不替代最终生产包、ARM 或 Windows 原生验收；打包输入实际 glibc 2.39，独立 CLI 归档的2.28基线声明不扩大到桌面包。

产品运行与正式性能验证范围仍是86d；最终 tag/master 上的 `build_id` 绑定实际发布提交，生产资产哈希也须重新取得。不能给本地86d、前两次unknown产物或既有包改标签冒充最终生产构建。

发布工作流只在版本tag触发：先创建draft，等待四平台桌面、四平台独立CLI及两架构Flatpak验证完成，再以固定公钥核验四个平台updater制品及签名中的版本/文件名，公开prerelease后只推进Preview。当前Stable原无索引，维持原状态；不以alpha发布创建或覆盖Stable。签名Secret仅核对名称存在，没有读取值或本机敏感目录。

隔离测试签名不替代生产签名，WSL extraction fallback不证明物理FUSE挂载，Linux x64/Windows runner不证明ARM64物理桌面交互。离线包替换也不证明生产网络下载；最终发行工作流须完成生产签名、目标制品与通道结果核验后才能公开版本。发布后的Release URL、实际资产哈希与通道结果记录在发布凭据中。
