# DezirClip v0.2 执行规范

状态：实施中。批准依据：2026-10-19 用户提供的执行 Spec 与分阶段 PR、审查后合并及发布要求。

本轮实现基线为 `802808b06e6b795064c5065d1d880bae9b193b9a`（已发布 v0.1.20）。原方案的 `0d3bedd5` / alpha.3 已被主线更新取代。开始工作时存在的其他会话改动不属于本轮 PR；使用独立工作目录。

## 交付与审查

每项进度交付独立可审查 PR，附接口说明、兼容性、验证证据、性能影响和限制。实现、构建成功与 reviewer 通过是三个不同状态。

- 每个 PR 必须获得针对当前 head 的明确审查结论，所有意见修复并复核后才可合并；没有评论或旧 head 的通过不能替代当前审查。
- 依赖 PR 合并后，后续 PR 基于最新 master 更新并重新验证。禁止把未经审查的累计实现直接发布。
- 可以并行实现互不依赖的 PR；不能绕过依赖的验收和审查门槛。
- 不自动发布中间 v0.1.21。本轮发布目标为 Phase 0–2 全部完成的 **v0.2.0-alpha.1**。
- 发布版本号、安装包、内置 dzc、独立 CLI 与发布说明必须一致。发布 PR 同样经过审查。
- 所有目标的制品、签名和校验完成后才公开版本并更新对应通道。缺包、签名错误或验证失败时不推进通道。

## 全局约束

### 兼容

保留 GUI、Quick Paste、CLI、TUI、MCP、Shell Integration；dzc 现有命令和默认输出语义兼容。桌面与独立 CLI 分别构建打包。数据库事务迁移保留历史；旧程序面对不支持的结构拒绝写入。Windows / X11 原位升级不要求重建数据库。

### 性能

默认 GUI 直接链接 Core，不增加 daemon 或 IPC。大图片、HTML、二进制不反复 Base64/JSON 编解码或通过事件广播正文。保留缓存预算、延迟初始化、空闲 WebView 销毁、按需加载与 release LTO。

关键路径使用相同环境、数据集和采样方式比较基线；p95 退化上限取基线 10% 与 20 ms 中较宽松者。可选服务单独记录空闲私有内存、CPU、唤醒次数，共享映射不重复计费。没有测量时标记未验证，构建和节点数量不能证明运行性能。

### 安全和范围

敏感加密失败不能降级明文；核心策略独立于窗口状态；日志及错误不含剪贴板正文；MCP 不绕过访问策略。不开放本地 TCP/HTTP，IPC 只使用当前用户可认证的本机通道。

软件更新是本轮唯一新增的联网能力，仅访问固定 GitHub HTTPS 更新资源，可关闭自动检查；Core、MCP、捕获服务保持离线。此次更新模块是原知识库“无联网功能”的明确限定例外。沿用现有发布工作流完成签名与门槛验证，属于用户执行 Spec 对既有发布流程的修改，不另设通用 CI 系统。

不增加 macOS、云同步、账户、远程公开 API、联网凭据检测、LLM、Rust 动态库热加载或强制 daemon。

## Phase 0：敏感持久化安全

### P0-A：失败即拒绝

- `encrypt_sensitive` 返回明确 `Result`，区分 `KeyUnavailable`、`EncryptionFailed`、`SensitivePersistenceRejected`、`ProtectedRecordUnavailable`。
- 密钥不可用、密钥库锁定、随机数或加密失败均显式报错；portable 不得静默绕过保护。
- content、preview、HTML 等待保存字段全部保护成功后才写入；普通记录保持原行为。
- 历史密文不能在解密失败后当明文编辑、再加密或转存；原有可解密记录、备份和恢复保持兼容。
- 确定性注入故障覆盖新增、已有记录编辑、多个字段的中途失败；错误不包含输入正文。Windows DPAPI 和 Linux Keyring 的真实验证与模拟故障分别记录。

### P0-B：完整原子性

- GUI、CLI、TUI 共用 repository 边界；敏感标签及对应内容保护在一个事务内完成，失败标签和字段均不改变。
- 捕获在创建附件、OCR、预览或搜索索引之前判断保护。暂未实现二进制加密时，明确拒绝敏感图片/附件的持久化。
- 迟到的 OCR / 后台任务重新检查记录保护状态。敏感转换同时处理已有 OCR、FTS 和缓存，拒绝的操作不产生新明文衍生物。
- 保存失败返回可识别状态，不以 `id == 0` 或已有 id 伪装成功；不广播成功事件。
- 故障回归覆盖标签、附件目录、FTS、OCR、备份 Replace/Merge 回滚和普通记录对照。

本阶段不改识别器、数据库内容格式或用户敏感识别设置。

## Phase 1：简单自动更新

### 安装器

NSIS 保持 currentUser 与 passive 升级；验证签名后退出应用并安装、允许重新启动；安装位置、数据库、设置、内置 CLI 和路径保留。升级跳过卸载恢复，不重启 Explorer。

真正卸载仅恢复 DezirClip 有持久修改凭据、且当前仍是应用写入值的项目；原值不存在时恢复不存在。未知或用户后来修改的值保留，不无条件重置策略。首次从旧版迁移必须用旧安装器验证：新 hook 不能修改已经安装的旧卸载二进制，不能据新代码宣称旧清理路径已安全。

AppImage 仅在可写安装位置支持原位替换；只读安装给出明确错误与下载入口。deb/rpm/Flatpak 不使用 AppImage 包覆盖；独立 CLI 自更新不在本阶段。

### 签名与通道

使用 Tauri 2 官方 Updater，`createUpdaterArtifacts: true`，公钥内置，私钥与密码仅存受保护发布 Secrets，不提交仓库。校验和不能替代更新签名。所有 Windows NSIS 和 AppImage 目标制品及签名验证后，再发布通道索引。

固定 HTTPS `stable.json` 和 `preview.json`：Stable 仅正式版；Preview 可接受较新预发布或正式版；按 SemVer 判断、不降级。索引含 version、平台 URL、signature，仅指向已上传且验证的 Release 附件。签名失败、缺包或校验失败不得推进索引。

### GUI 与验收

设置提供自动检查开关、Stable / Preview、立即检查、当前与可用版本、更新日志、下载/安装进度、失败原因。启动检查非阻塞并限频；用户明确选择安装，默认不静默安装。离线不影响主程序。

验证通道筛选、错误签名拒绝、NSIS 原位升级及系统设置保留、AppImage 可写/只读、GUI / sidecar 同版本。未装 Updater 的旧版允许一次手动覆盖迁移。无差分更新、自动回滚或系统包管理器替代。

## Phase 2：Core 独立（alpha.1 主体）

### P2-A：Workspace

统一版本和依赖的单仓库 Cargo Workspace：`crates/dzc-core`、`crates/dzc-platform`、`crates/dzc-protocol`，服务暂只保留清晰扩展位置；`src-tauri` 作为桌面适配层，dzc 保持命令入口。

Core 负责模型、SQLite 迁移和存储、历史、分类、去重、缓存预算、加密策略、附件、搜索、标签、备份和捕获业务。不得依赖 Tauri、GTK、WebView、窗口状态或具体 Win32/X11/Wayland API。

同步修正 sidecar、独立 CLI、版本脚本和发布产物路径。保持独立无桌面依赖构建命令，记录迁移前后的等价命令与 JSON 契约证据。

### P2-B：捕获业务

以纯 `CaptureContext`、`CaptureEngine`、`EventSink` 替代 AppHandle 上下文。顺序：平台事件及来源元数据 → 预判断 → 按需读取 → 解析分类 → 隐私策略 → 去重保存 → 必要衍生处理 → 结构化结果。结果区分 `Stored`、`Skipped`、`Rejected`、`Failed`。

平台监听 worker 也不依赖 Tauri；桌面适配层负责窗口隐藏策略、声音、粘贴队列、Tauri 事件和运行时任务。保留现有 Windows/X11 行为，不把 AppHandle 依赖简单搬到另一个 Core 文件。

### P2-C：接口与策略基础

细粒度平台接口：`ClipboardReader`、`ClipboardWriter`、`ClipboardMonitor`、`PasteController`、`SourceResolver`、`ShortcutProvider`、`PrivacyHintProvider`。只实现实际支持的能力；不可用明确返回 Unsupported 和原因。

`PlatformCapabilities` 至少报告 read、write、monitor、auto_paste、global_shortcut、resolve_source、read_privacy_hints。Core 对外暴露 HistoryService、ClipboardService、PrivacyPolicy、CaptureEngine、BackupService、EventSink 等业务接口，不能把裸 Connection/内部缓存作为最终公共 API。GUI、CLI/TUI/MCP 共用逻辑、类型和错误。

PrivacyPolicy 分离 Evidence 与 Decision：证据记录来源、规则、等级和稳定原因码；决策至少 Allow / Encrypt / Skip / SessionOnly（预留）。证据等级不伪装为未验证的统计概率；本阶段不提前改变所有隐私 UI。

验收：Core 无图形环境可构建测试；捕获流水线无 AppHandle；既有数据库无需重建；CLI/MCP 契约兼容；Windows/X11 不退化；重构前后可比性能报告；默认无新常驻服务。

## 后续 Alpha

### alpha.2：可选服务

默认 Embedded；可选 Service 退出 GUI 后继续捕获。每用户图形会话一个捕获所有者，使用 OS 锁与明确交接，服务故障可恢复。Linux UDS / Windows Named Pipe 限定用户身份，长度分帧、有界请求、请求 ID；握手交换 protocol/core/client 版本及 capabilities，不兼容拒绝写入。

最小协议包括 hello/capabilities、health、history list/get/search、clipboard.copy、privacy get/set、events.subscribe、service status/stop。事件仅含 ID、修订和元数据；断线重连重新取状态。CLI 增加 service start/stop/status、capabilities、privacy status，MCP 不自动获取管理权限。

### alpha.3：隐私模式 2.0

信号优先级：用户隐私会话、系统明确禁记标记、来源排除、已验证凭据、上下文疑似。普通邮箱、手机号、密码复杂度不默认强制保护；扫描失败/超预算标记未完成，不宣称安全。已保护历史不因规则变更自动降级。

Windows 尊重 ExcludeClipboardContentFromMonitorProcessing 和 CanIncludeInClipboardHistory=0；Linux 尊重可获得的 x-kde-passwordManagerHint=secret，尽量先查元数据再读正文。

隐私会话 GUI/CLI/TUI 同步，支持 on/off/status 与限时；不自动产生记录、附件、OCR、索引、正文预览或事件，不删旧历史、不阻止系统剪贴板。手动新增有独立明确意图。捕获 epoch 在提交前复查，旧任务取消；重启不能无提示丢弃持续保护。无法确认共享状态不得报告开启成功。

完整保护正文、HTML、附件、OCR、索引、缓存、备份与外部接口；MCP 默认不可读敏感记录，GUI 主动查看与自动化分权。反馈支持非敏感纠正、来源忽略/保护、精确可撤销例外，不能将整个凭据类别永久放行。

### alpha.4：Wayland Clipboard Experimental

原生后端优先 ext-data-control-v1，回退 wlr-data-control，无协议明确失败；不依赖 wl-copy/wl-paste/xclip/xsel。第一批 CLIPBOARD 读写、监听、MIME 和 selection owner 生命周期，复用 Core；PRIMARY、全局快捷键、自动粘贴和完整桌面交互不作为第一批承诺。

能力检测基于实际连接、协议版本、seat、Portal 和权限，不能仅靠桌面名或 XWayland。GUI 隐藏/禁用不可用功能并说明原因，不用 xdotool 假装原生支持。窗口透明、置顶、焦点、截图分别报告。

允许 headless/nested Sway、虚拟机等协议测试；文档列出实际验证的 compositor 版本和功能。未做真实桌面验收的快捷键/粘贴/焦点不得声称完整支持。Wayland 进度不阻塞 Windows/X11 后续稳定版。

## 发布门槛

alpha.1 必须具备 Phase 0–2 每项 PR 的 reviewer 结论与对应 head、最小回归和构建证据、兼容说明、性能报告、受保护签名配置以及完整制品。记录未验证的平台边界；不得以未执行的跨平台 QA 作为完成证据。alpha.1 公开前最后核对未解决审查、版本一致性、安装迁移、通道目标及签名。
