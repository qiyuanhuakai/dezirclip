# v0.2 P2-C：共享业务 API、能力与隐私证据

## 公共边界

依赖方向为 Desktop / CLI → Core + Platform → Protocol；Core 不依赖 Tauri、原生剪贴板或 Platform。新增 dzc-protocol 仅包含 serde 值类型、版本兼容判断、能力与稳定错误原因，没有 IPC、网络、调度器或进程状态库。protocol 1.0 的兼容判断要求 major 相同，不承诺尚不存在的进程通信。

Core 的 api::HistoryService 持有存储实现，以 HistoryQuery / HistorySearchMode 提供查询、保存、编辑、标签、删除、排序和统计。api::BackupService 复用同一服务的严格完整记录读取、附件备份及原子恢复。CLI、TUI、MCP 和桌面的历史列表、搜索、标签库、编辑与导入导出实际经过这些接口；MCP 仅得到 AutomationHistory，其查询必须有 1..1000 的上限，并在解密之前强制排除敏感记录。现有 CLI 参数、输出和备份格式保留。

不启用 feature 时 database、infrastructure、内部 services 均私有。legacy-bridge 为显式、非默认 feature；legacy 模块和迁移构造器有 doc(hidden)，仅供当前 Desktop 组合事务、设置、OCR 及未迁完的原生操作使用，不属于稳定 API。桥内仍存在 Connection / cache 等接口，不能作为第三方 SDK 契约。Desktop 通过 from_legacy_parts 共享现有 repository 的连接、缓存和预算；没有为每次调用重建独立缓存。

crypto 与 filesystem 是 Platform 所需的窄出口，不公开数据库连接。HistoryService::capture_store 返回细粒度 CaptureStore，共享同一 repository 的附件、加密与清理事务；Core 的 headless 示例通过公开 CaptureEngine 实际提交并由 HistoryService 回读，不需要 legacy 或 Connection。未安装密钥 provider 时，敏感保存返回 KeyUnavailable 并保持原记录。

## 原生 ports 与运行时能力

ports 包含 ClipboardReader、ClipboardWriter、ClipboardMonitor、PasteController、SourceResolver、ShortcutProvider、PrivacyHintProvider。ClipboardService 实际处理 CLI / TUI 的原生读写；复制动作不隐式调用 PasteController。X11 独立 CLI 的 writer 继续使用既有 selection-owner helper，嵌入图形客户端应注入持有本进程 selection 的 writer。

capabilities --json 在打开历史数据库之前执行，scope 固定为 embedded_client。available 表示当前 adapter 的只读探测成功，active 仅表示本客户端正在运行的 worker / registration。独立 CLI 的一次能力查询不启动监听器，也不推断另一 GUI 进程是否正在运行。

| 能力 | Windows 证据 | Linux 证据 |
|---|---|---|
| read / write | 实际 OpenClipboard / CloseClipboard | 实际 X11 连接及 roundtrip |
| resolve_source | 当前有效 foreground window；解析先 clipboard owner 后 active window | 实际 EWMH active-window 属性；标明 ActiveWindow 来源 |
| monitor | 实际 message-only window 建立与 Add/Remove/Destroy | 实际 XFixes 协商；不可用时验证 polling connection |
| auto_paste | 当前 interactive foreground target；调用时检查 SendInput 返回数量 | 实际 XTEST/XKB、无已按键及修饰状态、第一组真实 key type/action/modifier map；调用时重新检查 |
| global_shortcut / read_privacy_hints | 此独立客户端没有 adapter，返回 AdapterUnavailable | 同左 |

探测不会读取剪贴板正文或模拟按键。权限和会话状态仍可能在探测后改变，实际操作会返回稳定 PlatformError。GUI 的复杂原生复制、热键、窗口跟踪、粘贴与焦点恢复仍由桌面 adapter 管理；本阶段统一历史/采集业务路由和独立客户端的原生读写 ports。已有 GUI 热键、窗口跟踪和粘贴队列继续由桌面 adapter 管理，未被独立 CLI 的 AdapterUnavailable 结论禁用；不能把该结论解释为整个系统不支持。

Linux 不依据 DISPLAY 存在便宣称可用；无图形会话、无 X11 的原生 Wayland 会话、连接失败、扩展缺失分别保留原因。连接到 XWayland 时 backend 仍是 X11，不宣称原生 Wayland 支持。monitor 运行于调用方的既有 worker，接口不承诺停止或取消。

独立 X11 PasteController 只支持有效与锁定 group 均为第一组、无 base/latched/locked/lookup modifier、无任何已按键及鼠标键的状态。按 XKB 当前组的 key type 解析 level 0，V 必须实际为小写 v，type 不消费 Control、无零修饰状态的其他 level 或特殊 action/behavior；Control 键须真实映射到且仅设置 Control。无法确认、非第一组、已持有按键或 AccessX/overlay 等影响输入的控制状态均返回 Unsupported，不切组、不清锁、不释放已有按键。探测不注入输入；实际调用重新读取上述状态，并短暂序列化其他客户端的请求，在同一连接排入 Ctrl/V 按下与释放后检查结果，失败只尽力释放本次已确认按下且尚未确认释放的键。该序列化不会冻结物理键盘、鼠标或焦点变化，不承诺阻止用户与自动输入同时操作的竞态。

Xvfb 原生测试使用独立 Xlib 的 XkbLookupKeySym 翻译真实收到事件的 state/keycode，验证 Control+v，而非用生产选键函数计算预期 keycode；另覆盖低 keycode 仅第二组含 v、当前第二组拒绝、当前组无 v、Control 重映射、Control 参与 level 选择及已持有 Shift/V 不被释放。Xlib 仅由显式原生测试按需加载，测试程序与生产 CLI 均不增加 libX11 的强制动态依赖。测试范围不代表已验证所有真实桌面、国际布局或输入法。

## 隐私证据与决定

PrivacyEvidence 分离 source、level、稳定 reason、可选 rule_id；rule_id 仅允许规则或来源标识，不能装入正文。旧检测器只返回聚合 bool 时，rule_id 固定为 legacy_configured_detector，表示整组已配置规则的匹配证据，不能据此推断具体类别或自定义表达式。来源排除、手工保护、已有保护与控制项使用固定标识；不把正文或完整 regex 放入 rule_id。

EvidenceLevel 的 Explicit / Matched / Unavailable / Incomplete 是证据状态，不是概率。PrivacyPolicy 将证据组合为 Allow、Encrypt、Skip 或 SessionOnly；保留原有暂停、来源排除、用户规则、去重继承保护和会话保存语义，不新增检测器或更改现有设置键。

缺少平台隐私信号不等于检查后没有信号；PrivacyHintProvider 必须返回明确 Unsupported。不完整扫描保留 Incomplete 证据。事件接口只分发元数据，可信调用结果中的证据不进入普通事件正文。真正持久化仍由 repository 的原子保护事务复查，本层决定不会绕过 fail-closed 规则。

本阶段完成共享接口基础；没有宣称完整 Privacy 2.0 检测覆盖、原生 Wayland、可停止监控或跨进程能力共享。
