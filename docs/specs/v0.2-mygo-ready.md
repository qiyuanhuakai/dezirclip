# DezirClip v0.2 — MyGo-Ready Architecture Specification

**状态：** Proposed  
**适用范围：** 原 v0.2 执行 Spec 的增量修订  
**长期目标：** Tauri/React 主界面与 MyGo Native Surface 可共存，并保留未来整体迁移 MyGo 的可能性。

## 0. 架构总原则

维持原 Spec 的 P0–P5 实施顺序和所有安全要求。

新增六条架构约束：

**MG-G1：GUI 框架可替换。** `dzc-core` 不允许依赖 Tauri、MyGo 或具体窗口系统。未来替换 GUI 不应该要求重写剪贴板业务逻辑。

**MG-G2：跨语言接口独立。** Rust 和 Go 客户端必须遵守同一份版本化 Wire Schema。Rust 类型不是协议定义本身。

**MG-G3：进程分离是可选的。** Embedded Core 仍为默认部署方式。MyGo Surface 启用时可以额外运行辅助进程，不得因此强制启用独立 `dzc-service`。

**MG-G4：捕获所有权唯一。** GUI、后台 Service 和 MyGo Surface 不得各自建立重复的剪贴板监听与保存流水线。

**MG-G5：控制与大数据分离。** 普通请求和事件只传 ID、状态与必要元数据；大型图片、截图、富文本资源按需读取或通过专用二进制通道传输。

**MG-G6：MyGo 实验不得影响稳定前端。** Native Surface 不达标时必须能够关闭，并继续使用现有 Tauri 实现。

---

# Phase 0 — 隐私安全补丁

保留原 P0 全部要求。

新增：

- 敏感记录的加密、存储和读取权限只能由 Core 决定。
- 将来 MyGo、Tauri 或其他客户端不得自行决定是否将敏感记录降级为普通记录。
- 外部 UI 不得直接获取主密钥。
- 敏感记录内容只经授权业务接口读取，不能因为使用新的 IPC 客户端而绕过原保护机制。

**验收补充：** 敏感加密失败的防明文规则不依赖具体前端和捕获进程。

# Phase 1 — 简单自动更新

保留原 P1 的 NSIS、AppImage、签名和通道设计。

新增未来混合前端兼容要求。

## P1-MG.1 组件版本一致性

发布包中的组件应属于同一个兼容版本集：

- DezirClip Desktop
- dzc CLI
- 可选 dzc-service
- 未来 dzc-surface

引入统一的 `build_id` 和组件版本信息。

不同版本客户端必须通过 IPC 握手判断兼容性，不允许依赖文件名推断版本。

## P1-MG.2 辅助进程更新生命周期

未来安装 MyGo Surface 时：

- 由桌面应用的更新机制统一交付 Surface 二进制。
- 更新前正常通知 Surface 退出。
- 不得在 Surface 持有窗口或文件句柄时强行覆盖运行文件。
- 更新后由主程序按需要重新启动。
- 不要求 MyGo Surface 单独安装更新器。

本阶段不必开发 `dzc-surface`，但更新流程不得假定应用永远只有一个可执行文件。

# Phase 2 — Core 独立及跨语言准备

保留原 P2 的 Rust Core、平台抽象和业务接口。

## P2-MG.1 Core API 边界

内部继续使用惯用 Rust 设计，包括 Trait、生命周期和异步任务。

对外业务门面优先采用明确的输入与输出类型：

- `EntrySummary`
- `EntryDetail`
- `SearchRequest`
- `SearchResult`
- `PrivacyState`
- `PlatformCapabilities`
- `DzcError`

不得把以下对象泄漏为对外业务契约：

- `AppHandle`
- `rusqlite::Connection`
- GUI 窗口句柄
- IPC Transport 对象
- 平台原生 HWND/X11/Wayland Handle

对外 DTO 不需要直接兼容 C ABI，但应当能够明确转换为可序列化的协议类型。

## P2-MG.2 Core 定义平台 Port

Core 定义能力接口：

- ClipboardReader
- ClipboardWriter
- ClipboardMonitor
- PasteController
- SourceResolver
- ShortcutProvider
- PrivacyHintProvider

由 dzc-platform 实现这些接口。

Core 不依赖平台实现；依赖方向只能从平台 Adapter 指向 Core 所定义的能力契约。

组装操作发生在 Tauri Desktop Host 或 dzc-service 中。

## P2-MG.3 不实现 FFI

v0.2 明确不开发 `dzc-ffi`。

未来 MyGo 首先通过 IPC 使用 Core。只有在实测表明独立 IPC 不适合目标部署，并确认嵌入 Rust Core 有实际收益后，才评估稳定 C ABI。

禁止提前为潜在 FFI 引入复杂的跨语言对象生命周期管理。

### Phase 2 新增验收

- [ ] Core 的业务门面不包含 Tauri 和 MyGo 专有类型。
- [ ] Core 可以独立测试。
- [ ] Core DTO 可以转换为稳定的协议消息。
- [ ] 平台适配器只负责平台操作，不维护自己的历史和隐私规则。
- [ ] 当前 Rust GUI/CLI 性能不因准备 Go 前端而明显退化。

# Phase 3 — 语言无关协议和可复用 IPC Host

这是本次修订中最重要的阶段。

## P3-MG.1 Wire Schema 成为唯一协议定义

建立：

```text
protocol/
  schema/
    envelope.schema.json
    history.schema.json
    clipboard.schema.json
    privacy.schema.json
    events.schema.json
    capabilities.schema.json
```

第一版建议使用 JSON Schema 定义消息、约束与版本。

Rust 和 Go 各自实现或生成协议 DTO，通过跨语言一致性测试验证。

不得要求 Go 客户端依赖 Rust crate。

Protobuf 暂不作为强制前置依赖。若之后发现 JSON 编码是可测量的性能瓶颈，再评估升级传输编码。

CLI 的现有 JSON 输出以及 MCP 的 JSON-RPC 契约保持独立，不必和内部 IPC 使用完全相同的消息包装。

## P3-MG.2 IPC 基础协议

采用：

- Windows Named Pipe
- Linux Unix Domain Socket
- 有界长度分帧
- UTF-8 JSON 控制消息
- 请求 ID 和明确的结果/错误结构
- 会话握手与协议版本协商

请求消息包含：

- `request_id`
- `method`
- `params`

连接初始化协商：

- `protocol_version`
- `client_version`
- `client_role`
- `capabilities`

未知字段按照协议版本的前向兼容规则处理；未知必需能力、无法识别的操作或不兼容协议版本必须明确拒绝。

所有稳定错误码使用语言无关的字符串或数字，不暴露 Rust 内部类型名。

## P3-MG.3 IPC 服务与独立进程解耦

将服务端 Transport 和请求路由实现为可复用 Rust Library。

允许两种部署：

**Embedded Host**

```text
Tauri Desktop Process
  ├ dzc-core
  ├ dzc-platform
  ├ CaptureEngine
  └ IPC Server
       └ MyGo Surface Client
```

**Standalone Service Host**

```text
dzc-service
  ├ dzc-core
  ├ dzc-platform
  ├ CaptureEngine
  └ IPC Server
       ├ Tauri Client
       ├ MyGo Surface Client
       └ dzc CLI/TUI
```

IPC 客户端看到的业务协议保持一致。

用户默认仍可只启动 Tauri Desktop，而无需长期运行 dzc-service。

## P3-MG.4 统一运行时状态与版本

定义：

- `service_instance_id`：标识当前 Host 实例。
- `history_revision`：历史数据库整体修订号，在相关事务中更新并持久化。
- `privacy_epoch`：隐私策略或隐私会话切换时递增。
- `event_sequence`：当前 Host 实例内的事件序号。
- `entry_revision`：可选的单条记录修订号。

客户端断线重连后：

1. 重新握手。
2. 获取当前状态与修订号。
3. 与本地状态比较。
4. 必要时清空摘要缓存并重新查询。

第一版可以直接刷新数据，不要求实现复杂的增量同步或持久事件日志。

不得假定事件订阅永远不会丢失消息。

## P3-MG.5 客户端权限

引入最小权限客户端角色：

- `desktop`
- `surface`
- `cli`
- `mcp`

角色不是客户端自己声明后就自动获得权限。

连接须通过当前用户的 OS 身份检查及受控本地 Endpoint；需要额外操作能力时使用经可信 Host 授予的会话权限。

Surface 默认只可以：

- 查询受限的历史摘要。
- 搜索可见记录。
- 请求复制指定记录。
- 请求由 Host 执行粘贴操作。
- 订阅必要的历史与隐私状态事件。

Surface 不允许：

- 获取主密钥。
- 直接读写数据库文件。
- 执行任意 Core 管理命令。
- 修改敏感保护策略。
- 直接读取未授权的敏感正文。

## P3-MG.6 面向 Surface 的业务接口

在原有 IPC 方法之外增加：

- `surface.capabilities`
- `surface.history.list`
- `surface.history.search`
- `surface.activate`
- `surface.dismiss`
- `surface.copy`
- `surface.paste`

粘贴目标和窗口焦点恢复由具备平台能力的 Host 处理。

Surface 只表达用户选择了什么，不直接承担复杂的系统粘贴语义。

### Phase 3 新增验收

- [ ] 同一个 Go IPC Client 可连接 Embedded Host 和独立 Service Host。
- [ ] 不要求客户端知道服务内部是否运行 Tauri。
- [ ] 连接权限和请求范围均可验证。
- [ ] 重连后数据状态能够收敛。
- [ ] 大型图片正文不进入普通事件消息。
- [ ] 没有 MyGo 客户端时不增加非必要的持续后台负载。

# Phase 4 — 隐私模式 2.0

保留原有隐私识别与隐私会话目标。

新增跨前端原则：

- PrivacyPolicy 始终由 Core 管理。
- 隐私状态由当前 Capture Host 统一发布。
- MyGo 和 Tauri 订阅相同的 `PrivacyStateChanged` 事件。
- Surface 不缓存敏感正文或预解密附件。
- 隐私会话开启后，所有 Surface 必须立即刷新可见权限。
- 即使客户端没有及时接到事件，后续读取请求仍必须由 Host 重新鉴权。

对 Quick Paste：

- 普通模式正常显示授权可见的摘要。
- 隐私模式下显示明确的保护状态。
- 已有敏感条目默认隐藏或遮蔽预览。
- 不允许依靠本地 GUI 缓存绕过隐私策略。

# Phase 5 — Wayland Experimental

保留原有原生 Wayland Clipboard Backend 实现范围。

新增两项边界：

**第一：Wayland Clipboard Backend 与 Wayland Surface 是不同功能。**

Rust 的后台剪贴板监听由 dzc-platform 负责。

MyGo 的 Wayland Panel 能否显示、获得键盘焦点及呼出，由 MyGo 与目标合成器的实际能力决定。

MyGo 的 Wayland 支持不等于 DezirClip 的 Wayland 剪贴板监听已经完整支持。

**第二：所有能力继续使用 Runtime Capability。**

不能因 MyGo 提供某项桌面 API 就在所有 Wayland 合成器中默认启用它。

不得为了获得全局截图、自动粘贴或快捷键能力而绕过合成器权限。

MyGo Surface 的 Wayland 适配可以延后至独立实验阶段，不阻塞原有 Windows/X11 Core 重构。

# Phase 6 — MyGo Native Surface Prototype

**状态：** 新增长期实验阶段  
**依赖：** Phase 2、Phase 3  
**不要求 Phase 4 和 Phase 5 全部结束后才能开始原型  
**目标：** 用 MyGo Native UI 替换 Quick Paste 的 WebView 浮层。

## P6.1 新增独立 Go 前端

建议目录：

```text
frontends/
  dzc-surface/
    cmd/
      dzc-surface/
    client/
    theme/
    components/
    surfaces/
      quickpaste/
```

采用固定、经过验证的 MyGo 版本，不在生产构建时自动跟随最新版。

首个版本仅实现 Quick Paste。

不实现完整历史管理器、设置页面或第二套 SQLite 访问层。

## P6.2 启动与生命周期

新增可选设置：

`Quick Paste Renderer: Tauri / MyGo Experimental`

默认继续使用现有 Tauri 版本。

用户启用 MyGo 后：

- 主程序按需启动 dzc-surface。
- 建立本地 IPC 连接。
- 创建隐藏的原生 Quick Paste Panel。
- 监听主 Host 的相关事件。
- 需要显示时直接定位、聚焦并 Show。
- 关闭时 Hide，不重新创建整个窗口。

允许实现惰性启动和可配置空闲退出。

不得每次快捷键触发都强制执行完整的进程冷启动。

## P6.3 统一快捷键所有权

同一个全局快捷键只允许一个注册者。

优先由当前桌面 Host 的 ShortcutProvider 负责注册。

快捷键触发后通过内部事件请求 Surface 显示。

切换 Tauri/MyGo 渲染器时，需要安全地迁移快捷键回调，不得出现两个浮层同时弹出。

## P6.4 Quick Paste 数据协议

Surface 只读取轻量摘要：

```text
EntrySummary
  id
  revision
  kind
  preview
  tags
  pinned
  timestamp
  source_app
  privacy_visibility
```

初次查询不返回完整正文、HTML 或 PNG。

支持分页、搜索、选中后的按 ID 操作。

Surface 的搜索索引以 Core 结果为准，不维护另一套独立业务搜索逻辑。

## P6.5 用户粘贴流程

```text
Hotkey
  → Host identifies target context
  → Surface.show
  → User selects entry ID
  → Surface requests paste
  → Host reads authorized content
  → Host writes native clipboard
  → Host restores target focus
  → Host invokes PasteController
  → Surface hides
```

MyGo 不直接访问加密数据库。

粘贴失败必须保留原有的可恢复交互语义。

## P6.6 性能评估

实际对照、输入身份、原件哈希及未覆盖范围见 [Phase 6 性能记录](phase6-performance.md)。记录中的描述性结果与本节完整验收要求分别核对。

必须分别对比：

- 首次冷启动。
- 已预热窗口的呼出延迟。
- 从按键到首次可交互帧的 p50/p95。
- 列表搜索与键盘选中延迟。
- 浮层隐藏后的总进程 PSS/USS。
- GPU 显存和共享映射内存。
- 空闲 CPU 与后台唤醒。
- 中文输入法、DPI、多个显示器。

与相同数据和相同窗口功能下的 Tauri Quick Paste 对比。

原生方案进入默认版本的初步目标：

- 热启动呼出 p95 明显优于当前 Tauri 实现，建议以 25% 改善作为候选门槛。
- 不明显增加整个应用组合的长期内存成本。
- 不损失关键交互、隐私和焦点恢复能力。
- 没有明显的字体渲染、IME 或可访问性退化。

若性能收益不足，维持实验性选项，不强制迁移。

## P6.7 验收

- [ ] Windows 和 Linux X11 可以运行原生 Quick Paste。
- [ ] Tauri Quick Paste 可以通过设置恢复。
- [ ] 双进程不会重复捕获。
- [ ] 取消、粘贴、搜索与焦点处理正确。
- [ ] 禁止通过 Surface 绕过隐私权限。
- [ ] 与 Tauri 版本有可复现的性能对比。
- [ ] MyGo 故障不会导致 DezirClip Core 退出或数据损坏。

# Phase 7 — Native Screenshot Surface

**状态：** 条件性新增阶段  
**依赖：** Phase 6 成功

目标是逐步替换截图区域选择 WebView，而不是重写整个截图基础设施。

## P7.1 第一版保持 Rust 捕获后端

使用现有 dzc-platform 的截图能力。

MyGo 负责：

- 全屏选择层。
- 鼠标拖动与尺寸显示。
- 选区调整。
- 截图工具栏。
- 取消与确认。

不要假定 MyGo 当前提供完整的跨平台桌面屏幕捕获 API。

## P7.2 大型图像传输

不允许将原始全屏 RGBA 作为普通 JSON IPC 消息发送。

先抽象 Blob Transfer：

```text
BlobRef
  id
  size
  format
  width
  height
  stride
  expires_at
```

实现优先级：

1. 有权限保护的临时二进制文件或内存映射，用于原型。
2. Unix memfd / Windows 共享内存，用于优化。
3. 平台支持时采用更低复制成本的图形资源传递。

必须处理 Blob 所有权、大小上限、超时、取消和异常退出清理。

敏感截图不得遗留在不受保护的临时文件中。

## P7.3 不迁移捕获所有权

除非通过实测证明值得，否则：

- Screen Capture Backend 仍由 Rust 所有。
- MyGo 不维护第二套屏幕捕获后端。
- Core 不知道截图选择框由哪个 GUI 框架绘制。
- 截图操作结果仍使用 Core 统一保存和隐私策略。

Wayland 屏幕捕获须另外遵循 Portal 授权与相关限制。

# Phase 8 — 可选 MyGo Web Host 迁移

**状态：** Future / Not Committed  
**依赖：** Phase 6/7 的实际结果

仅当 MyGo 长期维护情况、性能和原生 UI 质量满足要求后，才启动本阶段。

目标形态：

```text
MyGo Host
  ├ React Web Main UI
  ├ Native Quick Paste
  ├ Native Screenshot
  ├ Native Toast
  └ dzc IPC Client
```

保留 React 组件与主要 CSS 资源，但将原先 Tauri 专属接口收敛成 Frontend Host Adapter。

适配范围包括：

- Tauri invoke。
- Tauri Events。
- Window API。
- Dialog 和系统路径。
- 文件与资源协议。
- 全局快捷键。
- WebView 生命周期。
- 更新与安装生命周期。

不得假定 React 页面无需修改就能直接在 MyGo Host 中运行。

不要求 MyGo Host 直接通过 FFI 链接 Rust Core。

**决策条件：** 只有新 Host 相比 Tauri + Native Surface 混合架构具有明确优势，才正式实施迁移。

# Native Design System — dzc-surface-ui

这部分作为 Phase 6 的子任务，不建立独立大型 GUI 框架。

## DS1. 统一设计 Token

建立独立于 UI 框架的设计规范：

```text
design/
  tokens.json
  icons/
  typography.json
```

定义：

- 颜色与主题。
- 字体及字重。
- 尺寸、边距。
- 圆角与阴影。
- 过渡时间与动画曲线。
- 紧凑列表的高度及布局规则。

从统一 Token 生成 CSS Variables 与 Go Theme 类型，逐步与既有 DezirClip CSS Token 对齐。

不得手工维护两套互不关联的颜色和尺寸定义。

## DS2. 薄封装

只为 MyGo 现有 UI Primitive 提供样式与产品约束。

首批组件：

- Surface
- SearchInput
- HistoryItem
- TypeBadge
- TagChip
- SensitiveMask
- IconButton
- Separator
- Tooltip
- ScreenshotToolbar

重点保持视觉一致性。

禁止重新实现基础文本编辑、IME、焦点管理、滚动、键盘事件分发和通用布局系统。

如果框架缺少可靠的基础交互能力，优先修复或等待上游，而不是把 dzc-surface-ui 演变为第二套 GUI Toolkit。

## DS3. 主题兼容

原型可以先验证代表性的明暗主题。

正式替换对应 Surface 前，必须处理现有 DezirClip 主题及颜色模式的兼容性。

不要求复杂玻璃效果逐像素一致，但视觉语义、文本可读性、强调色和交互状态应统一。

---

# 更新后的实施路线

| 阶段 | 主要内容 | MyGo 相关调整 |
|---|---|---|
| P0 | 敏感数据安全 | 保证所有客户端共用安全策略 |
| P1 | 自动更新 | 预留辅助进程更新生命周期 |
| P2 | dzc-core 独立 | Rust Core 不泄漏前端实现细节 |
| P3 | dzc-service + IPC | 语言无关协议、可复用 Embedded Host |
| P4 | Privacy 2.0 | Surface 客户端最小权限 |
| P5 | Wayland Experimental | 平台 Clipboard 与窗口 Surface 分离 |
| P6 | MyGo Quick Paste | 第一次原生界面实验 |
| P7 | MyGo Screenshot | 条件性迁移瞬时截图界面 |
| P8 | MyGo Web Host | 长期可选替换 Tauri |

P6 可以在 P2/P3 的接口稳定后提前开始实验，不需要等待全部 v0.2 功能完成。

P7、P8 不进入 v0.2 正式版的强制交付范围。

# 最终发布约束

在 MyGo Native Surface 正式启用之前：

1. 不允许删除原有 Tauri Quick Paste。
2. 不允许要求用户额外安装独立 Go 运行环境。
3. 不允许两个 GUI 进程分别监听和保存剪贴板历史。
4. 不允许增加未经授权的外部 IPC 入口。
5. 不允许将敏感正文默认暴露给 Surface。
6. 不允许因为试验新框架而改变 Core 存储和加密语义。
7. 不允许把单个 MyGo 进程的低内存指标直接作为整个应用变轻的证据。

**最终原则：DezirClip 的 Core 独立于前端；瞬时界面可以使用最合适的渲染技术；MyGo 应当通过实测证明价值，而不是作为架构升级的前置条件。**
