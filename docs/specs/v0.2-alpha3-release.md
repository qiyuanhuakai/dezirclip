# v0.2.0-alpha.3 发布验收

本版本包含已合并的 #123–#126 回归修复及本次发布准备。产品版本统一为 `0.2.0-alpha.3`，数据库仍为 schema 24，协议仍为 1.0。所有正式资产必须绑定最终发布标签的同一干净源码；不得替换已公开的 alpha.2 资产或移动其标签。

普通发布门禁从版本受控的 `package.json` 取得本次版本，核对真实 tag、来源和发行包身份；alpha.2 的历史恢复权限继续固定在原版本、原源码和原 release ID，不作为 alpha.3 发布入口。

版本升级复用 `pnpm run release:set-version <版本或标签>`；脚本统一处理四类版本文件和全部本地 Cargo 成员，先读取全部目标、校验所需版本结构再写入。普通 CI 通过同一脚本的 `--check` 只读检查一致性，正式发布另核对实际 tag，防止候选版本和验收工具再次分散硬编码。旧包基线不会随候选版本更新而改变。

发布前须完成：发布准备 PR 当前提交的自动 AI 审查、普通 CI、四个平台桌面和独立 CLI 构建、两架构 Flatpak 验证、四平台最终包原生组件身份，以及 Windows 真实签名安装升级与卸载。Windows 保留 0.1.20、alpha.1 两组旧版升级，并增加已发布 alpha.2 到本版本的升级，分别核对真实旧包、原数据库、数据和设置保留、三个组件的最终字节与实际构建信息。

版本公开后，Preview 索引仍须等待本版本的四份实际验收报告：公开资产、AppImage 更新、Windows 升级和正式性能。报告结构、哈希绑定和不可复用旧证据的要求沿用 [发布验收文件](v0.2-alpha2-release.md#发布验收文件)，其中 `version` 必须为 `0.2.0-alpha.3`，源码、release ID 和全部安装包及签名身份须来自本次发布。

AppImage 更新除既有 0.1.20、alpha.1 基线外覆盖已发布 alpha.2，保留签名拒绝和数据保留检查。性能报告使用最终干净提交重新采样，记录相同编译器及 Service 空闲资源；alpha.2 的报告仅作历史参考。

所有原生 Windows 验收在一次性 CI 环境执行。本机不运行用户已安装的程序，不访问用户剪贴板、历史或安装配置。Linux 原生验收使用独立 HOME、XDG、DBus、私有显示器及隔离命名空间，并保留原始收据。缺失的最终包或性能凭据不得填为通过。

UI 与截图修复的本地浏览器检查使用合成 IPC；它们不证明物理多屏截图、DWM 时序或 Linux 合成器快速重开行为。发布说明保留这些边界。
