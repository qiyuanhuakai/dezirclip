所有本地 Linux 原生验证均使用独立 HOME、用户/PID/网络/IPC 命名空间、DBus 和私有 Xvfb 或无显示器合成器。功能凭据不等同于正式性能样本，也不证明物理桌面的 Portal 授权界面。Windows 本机不访问用户剪贴板、历史或安装配置；原生安装和系统剪贴板验证在一次性 CI 环境运行。

最终运行时要求数据库结构为 24、线协议为 1.0；桌面和 CLI 的实际链接清单为 Core、Platform、Protocol、Host，Service 额外包含 Service。组件版本和来源提交必须与最终发布提交一致，不能只修改显示文字或重新标记旧二进制。

Stable 保持现有稳定版本。只有公开发布资产验收完成后才推进 Preview 更新清单。

发布工作流仅运行 `node scripts/updater-release.mjs publish-only v0.2.0-alpha.2`：验证四个平台签名后公开版本，保持更新渠道不变。公开资产、两个真实旧版 AppImage 更新、Windows 升级及正式性能验收完成后，执行 `node scripts/updater-release.mjs promote v0.2.0-alpha.2 ACCEPTANCE.json`。验收文件须包含 `status: "passed"`、`schema_version: 1`、版本、`source_revision`、`release_id`，以及八个安装包/签名资产的 `signed_assets`（名称、ID、大小、更新时间、SHA-256）。`gates` 的 `public_assets`、`appimage_updates`、`windows_upgrade`、`performance` 分别填写实际验收报告的 SHA-256。未完成验收、来源或资产变化时拒绝推进渠道；推进前重新下载并验签，不复用草稿时的检查结果。
