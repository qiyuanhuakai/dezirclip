# 数据安全、备份与升级

本页说明本轮改造后的源码和新构建行为；已发布的旧包不会因此改变。完整命令见 [CLI 手册](./cli.md#导出导入和手动迁移)。

## 备份能保留什么

GUI 和 CLI 使用同一套完整导出、恢复逻辑。备份保留正文、原始换行、HTML、图片原始字节、标签、置顶顺序、使用次数、内容分类和 OCR 文本，不使用列表中的截短预览代替正文。

图片附件会嵌入备份，迁移后无需原路径。文件列表和视频只保留文件引用；HTML 中引用的外部图片、样式和本地文件也不会自动打包。旧版本已经截短或规范化的原文无法凭空恢复。

导出先完整写入同目录临时文件，再替换目标文件。图片附件丢失、图片损坏、具备有效历史密文结构的字段无法解密，或写入失败都会报错，已有目标备份保留。数据库及其日志路径不能作为导出目标。

普通正文、摘要或 HTML 中的 `linux:`、`dpapi:` 前缀会原样导出；成功解密后也不会再根据明文前缀重猜加密状态。历史数据库未单独记录每个字段的加密状态，因此符合完整历史密文结构的字面文本，仍无法与无法解密的历史密文可靠区分；这类记录会保守地阻止导出。仅有前缀、短 Base64 或不符合 DPAPI 结构的普通文本不会被当成有效密文外壳。

明文 JSON 可能包含私人正文，包括用户选择导出的敏感内容。需要保密时使用 GUI 的加密备份，或 CLI 的加密导出选项；将口令与备份分开保存。普通数据库文件中的应用加密不能替代可迁移的加密备份：跨机器恢复应使用导出文件。

## 恢复失败与版本升级

`dzc import backup.json --mode merge` 保留备份中的 ID，并覆盖目标库的同 ID 记录；它不是按正文去重或自动合并两台机器的历史。

`--mode replace` 会替换全部历史，包括置顶和带标签的记录。替换前先导出当前历史：

```bash
dzc export before-restore.json
dzc import backup.json --mode replace
```

恢复在写入前验证图片和 ID，并在一次数据库事务中完成。中途失败会回滚，不删除现有历史，也不改写已有图片附件。

数据库迁移同样按事务执行。两个进程同时升级时会串行处理；升级失败保留原库，较旧程序遇到高于其支持范围的数据库会拒绝打开。GUI 和 CLI 应保持版本匹配，不能通过旧程序降级新数据库。磁盘或权限错误不会触发自动新建空历史，请排查错误后重试或从已有备份恢复。

GUI 和 CLI 可访问同一个用户数据库；其他连接提交后，仓库缓存会失效，后续读取获取新数据。数据库锁仍可能在长事务或磁盘问题下超时，此时调用会报错；失败不等于已完成操作。

## v0.2 P0-A：敏感加密失败时拒绝写入

敏感记录的正文、摘要和 HTML 先全部加密成功，再写入数据库。密钥不可用或任一字段加密失败时，新增记录不写入；已有记录的保存、编辑或保护转换保留原字段。新输入即使以 `dpapi:` / `linux:` 开头，也不能借此前缀跳过加密。具有有效历史密文结构但无法解密的字段，不能在编辑时当作明文覆盖。

底层敏感加密接口现在返回 `Result<EncryptedPayload, EncryptionError>`。仓库沿用原来的 `Result<_, String>` 调用契约，错误字符串提供稳定原因码，不包含输入正文：

| 原因码 | 含义 |
| --- | --- |
| `KeyUnavailable` | 没有可用于持久保护的密钥或密钥库 |
| `EncryptionFailed` | 随机数或加密操作失败 |
| `SensitivePersistenceRejected` | 当前保存方式不支持完整保护，拒绝持久化 |
| `ProtectedRecordUnavailable` | 历史受保护字段当前无法解密，拒绝修改 |

Portable 构建此前会保留敏感明文；现在明确拒绝新增敏感持久化。需要继续保存普通内容时，不能把失败提示当作保存成功。已经保存的普通记录和可解密的历史密文仍按原格式读取，不要求清空数据库。

P0-A 阶段拒绝敏感外部附件和含 OCR 正文的敏感恢复；后续 P0-B 将已有 OCR 纳入同一字段保护流程，见下节。敏感记录不接受迟到的新 OCR 明文。恢复的 Replace / Merge 仍使用事务，拒绝时不以空历史替换原库。捕获保存失败后停止后续分发，不能因为条目已有 ID 就广播保存成功。

迁移数据目录保留完整源目录。桌面共享连接及 SQLite 写事务在迁移期间阻止写入；另一个只读连接用 `VACUUM INTO` 生成包含已提交 WAL 内容的一致快照。在独立暂存目录内完成受保护路径重写和附件复制，全部成功后发布到空目标，最后原子替换 `datapath.txt`。密钥、SQL、复制或配置切换失败时，原库、原附件和旧配置仍可用；失败后可能留下未启用的目标副本，重试应选择空目标，不自动删除这些副本或覆盖已有目标历史。

成功切换后当前桌面连接保持只读，界面随即要求重启，避免重启前继续写入旧库。保存、删除和收藏文件命令在文件操作前检查该状态，排队的请求不会先删除附件再因 SQL 只读而失败。源副本不会自动清理，可在确认新目录和备份后自行处理。迁移时应关闭其他 CLI、TUI 或旧版客户端；SQLite 锁仅覆盖本次迁移，其他进程若在锁释放后继续使用旧路径，其后续写入只留在保留的源目录。目录不能互相包含，附件符号链接被拒绝；该操作不是断电可回滚的全文件系统事务。Portable 使用可执行文件旁的 `data` 目录，不能通过全局重定向迁移，应退出后搬动完整便携目录。

去重重采集继承原记录的标签，包含手动添加的敏感标签；自动检测关闭或规则变化不会因此降级保护。密钥可用时继续加密保存并更新原 ID；保护失败仍停止捕获分发。已有 ID 的读取和验证增加了开销；性能基线比较将在 Core 阶段完成，当前没有新的延迟测量结论。

P0-A 是 [v0.2 执行规范](./specs/v0.2-execution.md) 的首个独立补丁。标签事务、HTML 附件、已有 OCR、当前搜索索引及缓存由下述 P0-B 接续完成。两项补丁均不会自动修复已经泄露或写入的旧明文副本。

## v0.2 P0-B：统一敏感变更的提交边界

GUI、CLI 和 TUI 的单条标签修改共用仓库事务。新增敏感标签时，正文、摘要、HTML 和已有 OCR 必须全部保护成功，才一起提交标签与字段。密钥不可用、后续 SQL 或提交失败会回滚，界面不会先标记成功再排队加密。保护状态不因隐私规则变化或读取历史而自动降级；用户主动移除最后一个敏感标签时，才在同一事务内恢复可读字段。任一历史字段不可解密时，移除也会失败并保留原状态。系统敏感标签不能通过全局重命名绕过逐条转换；全局删除继续使用既有的记录与受管理附件清理流程。

图片、文件、视频、外部附件及含资源引用或不能完整解析的 HTML 尚无二进制保护方案，不能新增为敏感持久记录，也不能将这类已有记录标为敏感。失败保留原记录、共享附件和用户原文件。普通富文本捕获先在内存中规划图片路径，随后在仓库写事务内复查当前保护状态，完成字段和标签写入后才创建附件。失败仅清理本次新建文件，不覆盖或删除已有共享附件。敏感拒绝和持久化失败均停止成功分发。

HTML 附件规划在读取前限制单项 16 MiB、累计读取 32 MiB、最多 64 个需处理的本地资源引用。重复引用也计入读取预算；普通文件句柄采用有界读取，并复查实际文件类型。超限返回 `AttachmentBudgetExceeded`，整份计划被丢弃，不创建附件，不因短 HTML 引用大量本地图片而无限累计内存。该预算仅针对附件计划，不宣称限制所有剪贴板格式的总内存。

已有 OCR 使用现有的字段密文格式保护，读历史、标签列表、搜索和完整备份均走相同解码边界。升级会重置旧的桌面启动对齐完成标志，把遗漏的旧 OCR 纳入重试；密钥不可用或转换失败时不记录已完成。CLI 单独打开旧库时只立即升级索引边界，不强制对全部旧明文申请密钥重加密。迟到的 OCR 任务在写入时复查标签和全部保护字段，对已敏感或受保护记录拒绝新明文结果。恢复仍在一次事务内执行；可保护的富文本与 OCR 一同恢复，含未受保护二进制资源的敏感记录拒绝恢复。普通图片备份与恢复保持原有字节格式。

重采集缺少 OCR 时继承原结果；导入/恢复则以备份的 OCR 为准，显式空值清空目标旧 OCR，缺失状态使用 pending，不将目标旧识别词填回新正文。CLI 与 MCP 的敏感排除共用结构化密文判断，普通 `linux: kernel notes` 等 OCR 前缀不会被误隐藏；条件查询在解码匹配前完成保护判定。

启动历史对齐每批在一个事务内加密，并仅在批末重建一次全文索引；任一密钥、字段或索引失败回滚整批，不写已完成标志。单条可见记录转为受保护记录时，触发器在同一事务内通过 FTS5 的安全删除清理旧词项，不再对每条转换合并全库索引。任何索引维护失败仍使整个保护写入失败并回滚；不将索引清理推迟到成功返回之后。

数据库兼容版本升至 **20**，没有新增业务字段或密文格式。全文索引仍从过滤视图读取：敏感标签、无效标签 JSON，或正文、摘要、HTML、OCR 中具有有效历史密文结构的记录均不进入受管理索引。转换时在同一事务内清理旧索引并使仓库缓存失效；普通前缀文本仍可搜索。派生搜索索引启用 FTS5 `secure-delete`，可升级至 FTS 格式 5；连接同时启用 `PRAGMA secure_delete=ON`。这一组合避免仅逻辑删除后保留旧词项，也避免每条转换重组整个索引。迁移一次清理旧索引；不承诺追溯擦除旧 WAL、空闲页、旧备份或文件系统中的全部历史副本。具体兼容边界见 [索引维护说明](specs/v0.2-sensitive-index-maintenance.md)。

GUI 与 dzc 打开连接时注册只依赖传入字段的 `dc_search_visible(tags, content, preview, html_content, ocr_text)` 函数，标记为 deterministic 和 innocuous。版本低于 20 且遵守既有版本检查的客户端会拒绝打开新库，防止旧写路径重新写入敏感 OCR 明文。通用 SQLite 工具可读基础历史表；访问格式 5 的全文索引至少需要 SQLite 3.42，读取过滤视图、使用 FTS 的外部内容查询或写历史表还需要同语义函数。发行程序自带已固定来源的 SQLite，不依赖用户系统 SQLite 版本。仓库附带的 Python 集成与性能种子连接只在可信合成测试库中注册等价函数并遵守安全删除要求；它们不是生产写入接口，不应拿来导入用户历史。

## MCP 的隐私边界

`dzc mcp` 通过 stdio 提供只读列表、搜索、按 ID 获取工具，不监听网络、不执行剪贴板中的指令。

已有敏感标签或加密状态的记录，在解密和分页前排除。搜索不同模式、翻页或直接指定 ID 都不能绕过该过滤；被排除的 ID 返回不可用，不返回其正文或元数据。

**未标记的私人明文仍可被 MCP 客户端读取。** 过滤依赖标签和加密状态，不能判断所有私人内容，也不会扫描并保证识别密码、令牌或个人信息。只读表示客户端不能通过这些工具修改历史，不代表数据不会传给客户端；客户端如何使用读取结果取决于客户端自身。

MCP 使用当前用户的数据库，或显式的 `DEZIRCLIP_DB_PATH`。若只希望向 Agent 提供有限数据，可为它配置单独的数据库。按来源应用排除只影响后续捕获，无法识别来源时也不能保证排除；暂停捕获、标记敏感和清理已有历史是不同操作。

## 验证范围

Rust 回归覆盖升级失败回滚、同时升级、未来数据库保护、跨连接缓存、长正文/富文本/图片往返、恢复失败保留原附件，以及 MCP 的搜索/分页/指定 ID 过滤。运行：

```bash
cargo test --manifest-path src-tauri/Cargo.toml --all-targets
```

测试使用临时数据库，不操作用户历史。事务和回归测试提高可预测性，但不能恢复已经损坏或丢失且没有备份的数据。

无可用系统密钥库的 Linux 环境也会执行敏感保存和恢复回归：收到 `KeyUnavailable` 后，检查没有新增历史、标签关联或全文索引，Replace 恢复保留原有历史及索引。有可用系统密钥的平台仍验证实际密文和正文、摘要、HTML 往返；无密钥环境通过不代表已经验证该平台的密钥库成功路径。可独立运行 Core 与 CLI 全量测试：

```bash
cargo test --manifest-path src-tauri/Cargo.toml --no-default-features --lib
cargo test --manifest-path src-tauri/Cargo.toml --no-default-features --bin dzc
```

2026-10-19 本轮实测：WSL Ubuntu 的上述全量 lib 测试为 290 通过、1 项既有文件计时测试忽略，dzc 为 4 通过；系统密钥库处于锁定状态，定向运行确认实际执行了 `KeyUnavailable` 拒绝分支。Windows 的 `sensitive_` 定向测试 45 通过、`text_dedup` 2 通过，覆盖真实 DPAPI 保存及往返。没有为测试启用全局替代密钥；这组结果不代表已经验收 Linux 密钥库解锁后的成功路径或完成完整 Phase 0。
