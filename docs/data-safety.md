# 数据安全、备份与升级

本页说明本轮改造后的源码和新构建行为；已发布的旧包不会因此改变。完整命令见 [CLI 手册](./cli.md#导出导入和手动迁移)。

## 备份能保留什么

GUI 和 CLI 使用同一套完整导出、恢复逻辑。备份保留正文、原始换行、HTML、图片原始字节、标签、置顶顺序、使用次数、内容分类和 OCR 文本，不使用列表中的截短预览代替正文。

图片附件会嵌入备份，迁移后无需原路径。文件列表和视频只保留文件引用；HTML 中引用的外部图片、样式和本地文件也不会自动打包。旧版本已经截短或规范化的原文无法凭空恢复。

导出先完整写入同目录临时文件，再替换目标文件。图片附件丢失、图片损坏、记录无法解密或写入失败都会报错，已有目标备份保留。数据库及其日志路径不能作为导出目标。

明文 JSON 可能包含私人正文，包括用户选择导出的敏感内容。需要保密时使用 GUI 的加密备份，或 CLI 的加密导出选项；将口令与备份分开保存。普通数据库文件中的应用加密不能替代可迁移的加密备份：跨机器恢复应使用导出文件。

## 恢复失败与版本升级

`dzc import backup.json --mode merge` 保留备份中的 ID，并覆盖目标库的同 ID 记录；它不是按正文去重或自动合并两台机器的历史。

`--mode replace` 会替换全部历史，包括置顶和带标签的记录。替换前先导出当前历史：

```bash
dzc export before-restore.json
dzc import backup.json --mode replace
```

恢复在写入前验证图片和 ID，并在一次数据库事务中完成。中途失败会回滚，不删除现有历史，也不改写已有图片附件。

数据库迁移同样按事务执行。两个进程同时升级时会串行处理；升级失败保留原库，较旧程序遇到高于其支持范围的数据库会拒绝打开。GUI 和 CLI 应保持版本匹配，不能通过旧程序降级新数据库。磁盘或权限错误不会触发自动新建空历史，请排查错误后重试或从已有备份恢复。

GUI 和 CLI 可访问同一个用户数据库；其他连接提交后，仓库缓存会失效，后续读取获取新数据。数据库锁仍可能在长事务或磁盘问题下超时，此时调用会报错；失败不等于已完成操作。

## MCP 的隐私边界

`dzc mcp` 通过 stdio 提供只读列表、搜索、按 ID 获取工具，不监听网络、不执行剪贴板中的指令。

已有敏感标签或加密状态的记录，在解密和分页前排除。搜索不同模式、翻页或直接指定 ID 都不能绕过该过滤；被排除的 ID 返回不可用，不返回其正文或元数据。

**未标记的私人明文仍可被 MCP 客户端读取。** 过滤依赖标签和加密状态，不能判断所有私人内容，也不会扫描并保证识别密码、令牌或个人信息。只读表示客户端不能通过这些工具修改历史，不代表数据不会传给客户端；客户端如何使用读取结果取决于客户端自身。

MCP 使用当前用户的数据库，或显式的 `DEZIRCLIP_DB_PATH`。若只希望向 Agent 提供有限数据，可为它配置单独的数据库。按来源应用排除只影响后续捕获，无法识别来源时也不能保证排除；暂停捕获、标记敏感和清理已有历史是不同操作。

## 验证范围

Rust 回归覆盖升级失败回滚、同时升级、未来数据库保护、跨连接缓存、长正文/富文本/图片往返、恢复失败保留原附件，以及 MCP 的搜索/分页/指定 ID 过滤。运行：

```bash
cargo test --manifest-path src-tauri/Cargo.toml --all-targets
```

测试使用临时数据库，不操作用户历史。事务和回归测试提高可预测性，但不能恢复已经损坏或丢失且没有备份的数据。
