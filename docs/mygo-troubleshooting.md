# MyGo 退出诊断

MyGo 与 Tauri 继续共用 Rust 核心。Windows MyGo 的主快捷键和托盘切换只隐藏主窗口；达到启用的空闲销毁期限后才释放 WebView。窗口关闭按钮仍按原行为关闭 WebView。

贴边悬停唤出会显示完整窗口并保留贴边位置，短暂防误隐藏时间结束后可以再次收纳；普通托盘/快捷键唤出仍避开边缘。`Super+V` 是协议中的规范名称，与 Windows 的 `Win+V` 相同。启用系统接管须先经确认让 Explorer 释放，再注册快捷键。

Service 偶发退出仍需现场证据确认。数据目录（`clipboard.db` 所在目录）包含以下诊断文件：

- `service-lifecycle.log`：启动时间、PID、构建提交、正常退出或传输错误、系统错误码、Rust panic 的源码位置。超过 256 KiB 后在下一次启动轮转为 `service-lifecycle.previous.log`。
- Windows `service-native-exit.log`：未处理的原生异常码、故障地址、模块文件名及模块内偏移、PID 和线程 ID。超过 256 KiB 后在下一次启动轮转。不会保存内存转储；强制终止和部分快速失败不会经过此处理器，仍需结合内核退出码判断。
- Windows MyGo 的 `desktop-service-exit.log`：常驻进程观察到的 Host 内核退出码，可覆盖未执行 Rust panic hook 的原生崩溃或外部终止。超过 64 KiB 后在下一次记录轮转为 `.previous.log`。

这些文件不包含剪贴板正文、请求参数或 panic payload。普通隐藏不会轮询协议或写入日志；进程观察使用 Windows 内核句柄，不会自动结束任何进程。日志写入失败不阻止应用启动。

若再次出现托盘无响应，请保留这些当前日志（必要时包括 previous 文件）和发生时间。只有 `start` 而没有 Rust 退出记录不等于确定崩溃；需结合常驻进程记录的退出码和 Windows 应用错误事件判断。常驻进程先退出时无法观察随后发生的 Service 退出。

## 附件和预览

一次多文件复制仍是一条历史记录。主界面只在该记录内部逐项展示附件名称和缩略图；复制、拖出仍提交完整文件组。拖回应用自身不会复制；拖入会移除重复的规范路径，并复用已有的重复记录，即使普通历史去重关闭也不重复生成拖入记录。

附件预览只在获得当前隐私授权后生成，不向 WebView 发送本地附件路径。最多显示 256 个名称、为前 8 个附件生成缩略图；一次最多解码一个视频。视频显示第一帧，Windows 使用系统 Media Foundation，Linux 使用本机 ffmpeg（未安装或编解码器不可用时保留文件名）。解码在限时 3 秒的独立进程中运行，不写明文临时附件；当前预览输入上限为 16 MiB，超限文件仍可正常复制、打开和拖出。

Windows 来源图标查询不再要求读取其他进程内存，并支持与来源可执行文件匹配的 AppxManifest 图标及常见缩放资源。无法确认来源或读取图标时保留通用图标。MyGo 原生预览栏显示类型图标、来源图标和时间图标，受保护条目的来源图标仍遵循原有访问限制。
